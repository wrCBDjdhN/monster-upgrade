# 联机模式行为归属矩阵（net-mode-matrix）

> 前置审计文档 —— 对应计划 `.omo/plans/lan-multiplayer.md` Todo 8（B2），是 Todo 9（game_view 双模式分支）的实现依据。
>
> **阅读基准**：`views/game_view.py`（995 行，commit d571a1d，2026-08-11 实际读取核验）。计划中给出的 on_update 范围 606-946 经核验与实际一致：`on_update` 定义于 606 行、方法体结束于 946 行；`setup` 为 142-422 行。
>
> **产出用途**：todo 9 的 worker 依据本矩阵在 `on_update`/`setup` 入口按 `gs.net_mode`（'host'/'client'/'solo'）分支，无需重新审计即可实现客户端跳过逻辑。

---

## 0. 阅读说明

### 0.1 三模式语义（与计划 D1/D5/B1 对应）

| 模式 | 语义 | 本矩阵中的处理 |
|------|------|----------------|
| `solo`（单机，现状） | 单一进程同时是主机与客户端 | 全部段落本地执行，等价于「主机+客户端」合一；单机回归路径不受任何改动影响 |
| `host`（主机） | 权威世界模拟：怪物 AI/HP/掉落/宝箱/重生/战斗判定全在主机 | 执行全部「主机」+「双端」段，并额外承担广播职责 |
| `client`（客户端） | 纯表现层：只渲染 + 上报输入 + 接收快照 | 只执行「双端」段，⛔ 跳过全部「主机」段 |

### 0.2 符号约定

- **归属列**：`主机` = 仅主机进程执行；`客户端` = 仅客户端进程执行；`双端` = 主机与客户端都执行（多为表现层 / 本地输入）。
- **⛔** = 客户端模式必须禁用/跳过的段落（世界模拟或主机裁决逻辑）。
- 备注中的「数据流」形如 `本地玩家移动→上报`，箭头前为发起端行为，箭头后为主机处理/广播内容。

### 0.3 判定总则（对应任务要求）

- **客户端必须禁用**：怪物 AI 更新、怪物生成/刷新、掉落生成、宝箱生成与开启裁决、战斗伤害判定、怪物弹丸推进与碰撞、环境物破坏判定、撤离结算裁决、行动时间超时裁决。
- **双端保留**：渲染（on_draw→render_game）、粒子特效、漂浮文字、音效、HUD 绘制、本地玩家输入与移动、受击反馈（闪红/音效）、撤离读条本地表现、拾取乐观更新。
- **主机权威**：玩家 HP（HoT/regen/受伤结算）、掉落裁决、拾取仲裁、撤离清单、房间生命周期。
